# Security

Implemented controls include password hashing, signed 12-hour HTTP-only/SameSite cookies backed by revocable server-side session records, logout and logout-all, production secret checks, rejection of seeded `.test` accounts in production, CSRF-oriented Origin/Sec-Fetch-Site checks for state changes, security headers, credentialed CORS allowlists, request IDs, sensitive log redaction, configurable rate limits (150/minute default in production; preflight requests are exempt), structured errors, tenant predicates, server-side permission checks, hashed/expiring assessment tokens, candidate consent records, advisory integrity events, audit writes, and transactional credit accounting. The fake local evaluator, worker, checkout, and demo seed are prevented from handling production activity.

Before production, complete account lifecycle and session revocation, MFA, independent CSRF/CORS/CSP review, API-key hashing and rotation flows, webhook signatures and destination validation, signed private object access, malware scanning, retention/deletion jobs, immutable audit retention, abuse controls, dependency/security scans, incident response, and external penetration testing.

All AI output remains advisory in the user experience. The local scoring provider is a deterministic demo evaluator and is not suitable for candidate ranking or employment decisions. Integrity metadata is review context and must not be interpreted as proof of misconduct. Candidate code execution must remain disabled until an isolated, resource-limited sandbox is built and reviewed.
